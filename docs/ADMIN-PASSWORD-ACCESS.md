# Authorized Admin email/password access (#194)
This optional first-party session mechanism extends the existing Admin console and mapped RBAC. It does not enable local-key access in production or replace the signed proxy. No public signup.
- Provision identity in existing ADMIN_IDENTITY_ROLES_JSON; lowercase authorized email only. Generate a strong password hash using apps/api/scripts/hash-admin-password.mjs via protected stdin (not CLI arguments). Set ADMIN_PASSWORD_HASHES_JSON to a JSON map from email to generated hash through the deployment secret manager; never commit credentials/hashes. Set ADMIN_LOGIN_ORIGINS to exact trusted HTTPS admin origins. No password form is enabled with an empty credential map.
- Sessions expire after 8 hours; fresh token on login, session token hashed at rest, SameSite Strict/HttpOnly/Secure in staging and production. Mutations require trusted origin and matching session-bound CSRF header. Changing/removing a hash or mapped roles invalidates old sessions on next request. Admin sessions and rate limit state are durable through normalized PostgreSQL migration 914. Identity roles are looked up each request. Native sign-in and logout audit records contain hashed actor IDs.
- Rollback: remove ADMIN_PASSWORD_HASHES_JSON or roll back code; signed proxy remains supported. Keep additive session table until retention review. No secret values in logs.
